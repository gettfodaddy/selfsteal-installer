# Selfsteal Installer

Интерактивная подготовка nginx и локальной HTTPS-цели для Xray REALITY на Ubuntu/Debian. Установщик выбирает один из 20 локальных одностраничных шаблонов, выпускает сертификат и создаёт JSON **inbound** для ручного добавления в Remnawave.

## Что делает проект

1. Показывает информацию о сервере и слушающие порты.
2. Проверяет домен, IPv4 и порты 80 и 8443. Если порт 80 занят стандартной страницей nginx, предлагает сохранить её состояние и продолжить.
3. Сохраняет снимок затрагиваемых файлов, состояния nginx и UFW.
4. Устанавливает `nginx`, `certbot`, `ufw`, `openssl` и `curl` через apt.
5. Добавляет правила UFW для обнаруженных SSH-портов и TCP 80/443.
6. Выпускает сертификат Let's Encrypt через HTTP-01 и включает hook перезагрузки nginx после продления.
7. Размещает один из 20 шаблонов с собственной страницей 404 и favicon, создаёт `robots.txt` и `sitemap.xml`.
8. Настраивает nginx: HTTP на `0.0.0.0:80`, HTTPS сайта только на `127.0.0.1:8443`. Выбор синтаксиса HTTP/2 зависит от версии nginx.
9. Создаёт приватный и публичный ключи X25519, short ID и JSON inbound в защищённом каталоге `/var/lib/selfsteal-installer/`.
10. Проверяет nginx, локальный HTTPS, сертификат, пробное продление, HTTP-редирект, 404, robots и favicon; выводит результаты.

Xray и настройки Remnawave **не изменяются автоматически**. После установки требуется вставить сформированный inbound в Config Profile, применить профиль к нужной ноде и настроить Host. До этого публичная цепочка на 443 не проверена.

## Подготовка сервера

- Ubuntu или Debian с `apt`, `systemd`, `ss` из `iproute2`, Python 3.9 или новее и правами root.
- DNS: одна A-запись домена указывает на публичный IPv4 сервера; если домен в Cloudflare — режим **DNS only**. В этой версии наличие AAAA-записи блокирует установку: nginx для HTTP-01 настроен на IPv4.
- TCP 80 доступен извне для выпуска и продления сертификата. TCP 443 доступен клиентам для Xray.
- Порт 8443 должен быть свободен. Порт 80 может быть занят стандартной страницей nginx: установщик проверит конфигурацию и запросит подтверждение перед переключением. При обнаружении другого сайта или неподтверждённой конфигурации установка остановится. Порт 443 может быть занят Xray/Remnanode.
- Веб-сервер располагается на хосте. Для `dest: 127.0.0.1:8443` Xray должен видеть сетевое пространство хоста, например при корректной настройке Docker host network. Если Xray работает в отдельной сетевой изоляции, потребуется отдельно настроить достижимость nginx и адрес `dest`.
- Перед включением ранее неактивного UFW установщик отдельно показывает слушающие порты и запрашивает подтверждение. Откройте другие порты, необходимые вашим сервисам, прежде чем включать UFW. При наличии внешнего firewall у хостера его правила настраиваются отдельно.

На сервере удобно проверить DNS и порты:

```bash
getent ahostsv4 node.example.com
sudo ss -lntp
```

Замените `node.example.com` на свой домен. Если порт 80 уже обслуживает действующий сайт, эту версию установщика на нём запускать нельзя без изменения схемы. Для автоматического продолжения со стандартным nginx проверяются: принадлежность порта 80 системной службе nginx, отсутствие других слушающих портов nginx, наличие только сайта `default`, отсутствие дополнительных `conf.d/*.conf`, контрольные суммы стандартных файлов по базе `nginx-common`, подключённые конфигурации и ответ страницы `Welcome to nginx!`. Если хотя бы одна проверка не прошла, установщик объяснит причину и не изменит настройки.

## Публикация проекта в GitHub

### 1. Создать пустой репозиторий

В GitHub создайте **пустой** репозиторий, например `selfsteal-installer`. Не добавляйте при создании README или `.gitignore`: они уже находятся в проекте. Репозиторий можно сделать приватным.

### 2. На Windows открыть PowerShell в папке проекта

```powershell
cd 'C:\Users\Ivan\Pictures\selfsteal-installer'
git init
git branch -M main
git add .
git status
git commit -m "Add selfsteal installer"
```

Если Git попросит имя и email для коммитов, задайте их через `git config --global user.name` и `git config --global user.email` и повторите `git commit`.

### 3. Подключить и отправить репозиторий

Скопируйте HTTPS- или SSH-адрес только что созданного репозитория и подставьте его в первую команду. В примере `YOUR_USER` замените на свой логин GitHub:

```powershell
git remote add origin https://github.com/YOUR_USER/selfsteal-installer.git
git push -u origin main
```

При запросе аутентификации используйте GitHub CLI, Git Credential Manager либо SSH-ключ. Для HTTPS обычный пароль GitHub вместо токена не используется. Не добавляйте в репозиторий данные панели, ключи REALITY, сертификаты и резервные копии сервера.

## Установка на сервер

### 1. Подключиться по SSH

```powershell
ssh root@SERVER_IP
```

Замените `SERVER_IP` публичным IP сервера. Оставьте открытую SSH-сессию и обеспечьте доступ к VNC/консоли хостера, прежде чем включать firewall.

### 2. Установить Git и клонировать проект

```bash
apt update
apt install -y git python3
cd /opt
git clone https://github.com/YOUR_USER/selfsteal-installer.git
cd selfsteal-installer
```

Для приватного репозитория используйте SSH-адрес и настроенный для сервера ключ доступа. Не вставляйте токен в команду или URL: они могут остаться в истории и конфигурации Git.

### 3. Изучить и запустить скрипт

```bash
less selfsteal.py
sudo bash install.sh
```

Выберите пункт **1**, введите домен, публичный IPv4 и email Let's Encrypt. Установщик проверит DNS, покажет запланированные изменения и попросит подтверждение. Если UFW был выключен, понадобится отдельное подтверждение его включения.

По окончании запишите публичный ключ и short ID из отчёта. Приватный ключ находится в JSON, доступном только root:

```bash
sudo cat /var/lib/selfsteal-installer/reality-inbound.json
```

Не публикуйте содержимое JSON и не отправляйте его в общий чат: оно содержит приватный ключ.

Пункт **3** завершает установщик и возвращает вас в командную строку сервера. Также можно ввести `0`, `q`, `exit` или нажать `Ctrl+C`. В терминале доступны цвет и короткая анимация запуска; для отключения цвета задайте `NO_COLOR=1`, а для отключения анимации — `SELFSTEAL_NO_ANIMATION=1`.

### 4. Применить профиль в Remnawave

1. Откройте **Config Profiles** и выберите профиль нужной ноды. Сохраните его текущую конфигурацию отдельно.
2. Скопируйте JSON из файла выше и добавьте **объект inbound** в массив `inbounds` существующего профиля. Это не полный Config Profile: существующие `outbounds`, routing, другие inbounds и настройки нужно сохранить.
3. Если профиль уже содержит inbound на TCP 443, сначала разрешите конфликт портов. Два inbound не могут слушать один и тот же адрес и порт.
4. Примените профиль к нужной ноде и убедитесь, что Xray запустился. Проверьте, что `127.0.0.1:8443` достижим именно из сетевого пространства Xray.
5. В **Hosts** выберите этот inbound и укажите адрес сервера, порт `443`, SNI домена и параметры Reality. Используйте соответствующий публичный ключ и short ID, если панель не подставила их автоматически.
6. Обновите клиентскую подписку и проверьте соединение VPN с внешнего устройства.

Убедитесь, что профиль сгенерирован и используется на нужной ноде: если один профиль подключён к нескольким нодам, изменение может затронуть все эти ноды.

## Проверка после применения профиля

С компьютера или другого сервера:

```bash
curl -I https://node.example.com/
curl -I http://node.example.com/
curl -o /dev/null -s -w 'HTTP %{http_code}\n' https://node.example.com/no-such-page
curl -fsS https://node.example.com/robots.txt
openssl s_client -connect node.example.com:443 -servername node.example.com </dev/null 2>/dev/null | openssl x509 -noout -issuer -subject -dates
nc -zv SERVER_IP 8443
```

Ожидается доступный HTTPS-сайт, редирект с HTTP, код `404` для отсутствующей страницы и недоступный извне `8443`. Последняя команда должна завершиться отказом или таймаутом. Тест сайта не подтверждает работу VPN: отдельно проверьте подключение клиентом и выход в интернет через него.

## Откат

```bash
cd /opt/selfsteal-installer
sudo bash install.sh
```

Выберите **2**, затем подтвердите `yes`. Установщик восстанавливает затронутые файлы и прежнее состояние nginx, удаляет свои помеченные правила UFW и созданный им сертификат. Если UFW был выключен до установки, после удаления правил он снова выключается.

**Границы отката:** установленные apt-пакеты и их зависимости сохраняются; удаление пакетов могло бы затронуть другие сервисы. Изменения, внесённые вручную в Remnawave, Hosts, DNS и внешнем firewall, нужно откатить отдельно. Снимки хранятся в `/var/lib/selfsteal-installer/snapshots/` и могут содержать чувствительные данные: сохраняйте доступ к ним только для root.

При сбое установщик пытается выполнить откат автоматически. Если откат завершился с ошибкой, информация о текущем снимке сохраняется и пункт 2 можно запустить повторно. Резервная копия относится к известным файлам этого установщика и не заменяет полный снимок сервера у хостера.

## Шаблоны

Двадцать готовых вариантов лежат в `templates/`. Для просмотра всех вариантов откройте файл `preview.html` в браузере. В каждом шаблоне находятся `index.html`, `404.html` и `favicon.svg`; все стили встроены, внешние шрифты и скрипты не загружаются.

Чтобы пересобрать шаблоны после редактирования набора данных:

```bash
python3 tools/generate_templates.py
```

Шаблоны содержат демонстрационный текст. Перед использованием проверьте соответствие содержания вашему проекту.

```powershell

git status

```

```bash

```

Обновление файлов проекта не меняет уже установленную конфигурацию nginx. Не запускайте установку повторно поверх текущей: сначала разберите текущую конфигурацию или используйте предусмотренный откат.

## Проверка исходного кода

Локальные проверки меню, распознавания стандартной конфигурации nginx и восстановления из снимка не запускают nginx, Certbot или UFW:

```bash
python3 -m unittest discover -s tests -v
bash -n install.sh
```

Они не заменяют проверку полной установки и отката на тестовом сервере с Ubuntu/Debian, доменом и доступом к Let's Encrypt.
